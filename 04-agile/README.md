# 04 — Agilité (Scrum)

Module de 2 jours sur les méthodes **Agile** et **Scrum**, appliquées au métier de Data Analyst, à travers des ateliers pratiques.

## Compétences
- Définir le rôle de Product Owner
- Définir le rôle de Scrum Master
- Connaître les principaux termes de l'agilité
- Définir le backlog
- Donner un schéma de fonctionnement du Scrum avec les principaux moments (Product Owner, Scrum Master, daily stand-up, sprint, backlog, sprint planning, sprint review, rétrospective)

## Contenu

### Itération 1 — Démarrer en agile
- Pourquoi l'agilité pour des Data Analysts : incertitude des projets data, itérations courtes, hypothèse falsifiable, MVP
- Glossaire Agile / Scrum (15 termes : itération, sprint, product backlog, sprint backlog, user story, story point, vélocité, MVP, rôles, événements, critères d'acceptation...)

### Itération 2 — Construire un projet sous contrainte
- **Marshmallow Challenge** : construire en équipe la tour la plus haute avec contrainte de temps et de matériel (planifier vs itérer)
- **Mission « Sauver le Projet »** : arbitrage périmètre / délai / budget avec la grille OTOBOS, définition d'un MVP, tri MUST / SHOULD / COULD

### Itération 3 — Le cadre Scrum en pratique
- **Birdie Birdie** : simulation Scrum complète en Lego (4 itérations : estimation, planification, réalisation, revue, rétrospective KALM)
- Estimation avec l'eXtreme Quotation (1, 2, 3, 5, 8), story points et vélocité
- Critères d'acceptation et Definition of Done

### Itération 4 — Structurer un produit data
- **User Stories** : format *En tant que / je veux / afin de*, contrôle de qualité avec les 6 critères **INVEST**
- **Story Mapping** (cas de la médiathèque, phase 2) : colonne vertébrale du parcours utilisateur, épics, User Stories, empilement par priorité
- **Ligne de release (v1 / MVP)** : livrer une ligne horizontale de la carte, avec des tranches verticales (donnée → traitement → affichage) plutôt qu'un découpage par couche
- **Hypothèses & Spikes** : formuler une hypothèse réfutable avec un seuil chiffré, cadrer un spike (question précise, durée fixée, livrable = connaissance)
- **Application à un projet data personnel** : vision, épics, User Stories, ligne de v1, hypothèse réfutable
- **Rétrospective Speed Boat** : île, vent, ancre, iceberg
  
## Le cadre Scrum : 3 rôles · 4 événements · 3 artefacts

| | |
|---|---|
| **Rôles** | Product Owner (porte la vision, priorise le backlog, accepte/refuse à la review) · Scrum Master (facilite, lève les blocages, garde le cadre) · Développeurs (estiment, réalisent, livrent, auto-organisés) |
| **Événements** | Sprint Planning · Daily Stand-up (15 min) · Sprint Review · Sprint Retrospective |
| **Artefacts** | Product Backlog · Sprint Backlog · Increment |

### Déroulement d'un sprint

1. **Product Backlog** : le PO priorise ce qu'on veut faire
2. **Sprint Planning** : l'équipe s'engage sur ce qu'elle livre (estimation en story points)
3. **Sprint Backlog** : les éléments retenus pour ce sprint
4. **Daily Stand-up** : point quotidien de 15 min (fait / vais faire / bloqué)
5. **Increment** : résultat livré, fonctionnel et testé
6. **Sprint Review** : l'équipe montre ce qui marche, le PO accepte ou refuse
7. **Sprint Retrospective** : l'équipe analyse son fonctionnement (1 chose à garder, 1 à changer)
8. On recommence avec le **Sprint Planning** suivant

## Notions clés
- **Backlog** : liste priorisée de tout ce qu'on veut faire (user stories), portée par le Product Owner
- **Rétrospective KALM** : Keep / Add / Less / More, avec au moins une décision concrète pour le sprint suivant
- **MVP** : le plus petit livrable qui permet d'apprendre quelque chose de vrai sur la valeur, on coupe du périmètre sans dégrader la qualité
- **User Story** : besoin exprimé du point de vue d'un utilisateur réel (qui / quoi / pourquoi), jamais une tâche technique
- **INVEST** : Indépendante, Négociable, Valeur, Estimable, Small, Testable
- **Story Map** : vue d'ensemble du produit organisée selon le parcours utilisateur, avec les stories les plus indispensables en haut de chaque colonne
- **Tranche verticale** : story qui traverse toutes les couches (donnée, traitement, interface) et produit un résultat utilisable seule
- **Hypothèse réfutable** : « Nous croyons que… / Nous saurons que nous avons tort si… » avec un seuil chiffré
- **Spike** : investigation courte et bornée dans le temps dont le livrable est une connaissance (la donnée existe-t-elle, est-elle assez propre, ai-je le droit de l'utiliser ?), pas du code
